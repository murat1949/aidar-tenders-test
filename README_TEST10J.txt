3. CONFIG.TXT
config.txt содержит параметры доступа к Supabase.
Он нужен только компьютеру, который выполняет сбор и запись данных.

Пример структуры:
SUPABASE_URL=...
SUPABASE_SERVICE_ROLE_KEY=...

Важно:
- реальные ключи нельзя хранить в публичном GitHub;
- config.txt нужно хранить локально на компьютере-коллекторе;
- при переносе системы на другой компьютер config.txt создаётся заново
  с теми же актуальными параметрами Supabase.

9. РАБОТА С НЕСКОЛЬКИХ КОМПЬЮТЕРОВ
Текущая TEST10J состоит из двух частей:

А) Компьютер-коллектор
На нём находятся:
- Samruk Chrome profile;
- config.txt;
- TEST10J bridge;
- доступ к Supabase для записи данных.

Б) Компьютеры менеджеров
Им НЕ нужен config.txt и НЕ нужен секретный ключ Supabase.
Они открывают веб-портал и читают уже собранные данные из общей Supabase.

Таким образом, один компьютер может собирать и обновлять данные,
а несколько менеджеров могут одновременно пользоваться порталом
с разных компьютеров.

В текущей тестовой архитектуре запуск обновления Samruk выполняется
на компьютере-коллекторе, потому что bridge работает на 127.0.0.1.

Для коммерческой/офисной версии следующий этап архитектуры:
- вынести collector/backend в одно центральное место
  (выделенный офисный компьютер, сервер или VPS);
- хранить секрет Supabase только там;
- менеджерам оставить только браузерный доступ;
- при необходимости сделать центральную кнопку "Обновить Samruk",
  работающую не через localhost пользователя, а через сервер.
